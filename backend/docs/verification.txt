PACKAGE LAYOUT IN EVERY APPLICATION
com.credflow: owning Spring Boot application main class.
com.credflow.api: annotated HTTP mapping/parameter interfaces.
com.credflow.controller: REST implementations that delegate to services.
com.credflow.service: business logic and transaction coordination.
com.credflow.dto: typed requests, replies, receipts and internal delivery data.
com.credflow.entity: JPA entities with private fields and public accessors.
com.credflow.repository: own-schema JPA operations, queries and locking.
com.credflow.scheduler: background entrypoints that invoke the owning service.

Each lender now owns its service, repository, DTOs and entities inside its own
application source tree. There is no simulation library dependency. The only shared
library is member3-common, under the infrastructure namespace com.credflow.platform.
Its delivery entity moved to com.credflow.platform.entity; only Orchestration and
Integration scan that entity package. Bank apps load only their own SimCase and
SimCallback entities. No application depends on a peer executable application's JAR.
See docs/java-package-map.csv for every application's current class/source location.
